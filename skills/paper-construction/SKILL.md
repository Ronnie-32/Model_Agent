# Paper Construction

Use the analysis contract, approved architecture, structured outputs, `claim_evidence.csv`, source ledger when present, and final figures/tables. Read sections 8–9 of `docs/MODELING_PLAYBOOK.md` when needed.

## Evidence before prose

Do not generate a quantitative result while drafting. If a number or validation is absent from artifacts, return to execution rather than infer it from memory.

Before polishing, define:

- one-sentence paper thesis;
- direct answer for every requirement;
- claim-to-figure/table map;
- uncertainty and limitation wording;
- cross-question transitions.

In standard or rapid mode, put this in Final Analytical / Paper Story review and pause.

## Narrative

Expose the selected architecture, not the full internal search tree:

`question -> structural insight -> model rationale/formulation -> result -> falsification/uncertainty -> direct answer -> link forward`

The abstract/summary states the problem, unified framework, headline quantitative results, validation, and decision. Avoid model-name soup.

## Visuals and claims

Each figure/table must answer one reader question and show comparison or uncertainty when material. Use wording that matches evidence: association is not causation; selected/best-observed is not global optimality; stable in tested scenarios is not universal robustness.

Use only verified source-ledger entries. Respect current page, anonymity, AI-disclosure, bibliography, and supporting-material rules.

Run one final audit from the template. Do not reopen the full red team unless drafting reveals a contradiction.
